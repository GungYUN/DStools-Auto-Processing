## 1. 目标与范围

将依赖 Ultracool Sheet 的 ASKAP 处理程序改为可读取其他用户 catalogue 的全自动程序。通用化对象是输入表格、源标识、配置和结果管理；科学处理范围仍仅限 ASKAP。

工作在独立复制的项目中进行。原 `Ozstar_ASKAP_UCDs` 作为已验证基线保留；待原有运行检查完成后实施通用化，并通过本方案的验收再正式使用。

用户配置输入表格、列映射、输出位置和运行参数后，程序自动完成查询、下载、Slurm 提交、共享建模、逐目标减源与提取、裁剪、状态记录和符合条件后的清理。不要求逐源编辑命令，不引入交互式画图或人工掩膜步骤。

已有机制应继续保留：

- 登录节点访问 CASDA 和提交任务；计算节点离线处理。
- 同一观测共用 preprocess/create-model；各目标独立 insert/subtract/extract/crop。
- 默认 4 个独立观测槽，每槽 8 线程，总内存默认 160G；可配置。
- 根据工作量估时与分批，48 小时为默认上限，不是每次固定申请时间。
- 普通运行记录观测失败并推进；历史失败由显式 `--retry-existing` 启动有限重试。
- 只用规定产物的文件存在情况检查完成，不增加 DS/FITS 内容格式验证。
- Ada 主动拉取、SHA256 校验、逐文件传输记录；DS/I/V 三件套全部验证成功才记为传输完成。

## 2. 配置文件设计

### 2.1 可读性与组织

参考本地 `/PATH/TO/polkat/oxkat/config.py` 的分隔线、功能分块和逐项说明风格；该文件是设计参考，不是运行依赖。

`config.py` 使用清晰的赋值及小型参数字典。每个用户设置说明用途、类型、单位、默认值、允许值、`None` 的含义及关联限制；科学参数补充对结果的影响。可使用中英文注释，便于共享给其他使用者。解析、校验和命令生成实现放到模块中，不让用户配置文件承担大量实现逻辑。

| 顺序 | 分块 | 内容 |
| --- | --- | --- |
| 01 | 输入与输出路径 | catalogue、工作区、产物目录 |
| 02 | 表格与列映射 | CSV/FITS、FITS 表扩展、必需与可选列 |
| 03 | 坐标与自行 | 坐标单位、参考系与历元、自行单位及 cosδ 约定 |
| 04 | 处理范围 | Processing_Index 起止；默认全表 |
| 05 | CASDA 查询与下载 | 曝光、质量、SB、大小、半径、查询限制与下载重试 |
| 06 | ASKAP 预处理与建模 | preprocess 说明、create-model 非交互式选项 |
| 07 | 插入与减源 | 保护掩膜、固定分离减源 MS 的说明 |
| 08 | 动态谱与裁剪 | extract-ds 非交互式参数、I/V 裁剪尺寸 |
| 09 | 资源与估时 | 并行数、线程、内存、临时盘、耗时估计和作业上限 |
| 10 | 运行环境 | SIF、Apptainer bind、Python、模块、Slurm 站点设置 |
| 11 | 恢复与传输 | 有限重试、日志、远端路径、凭据文件位置 |

配置优先级：显式 CLI > 环境变量 > `config.py`。启动时记录最终生效值及覆盖来源，避免旧环境变量无声覆盖用户编辑。只提供有意义的 CLI 覆盖项，不要求所有设置都有对应命令行参数。

密码不写入配置和日志，仅配置账户与凭据来源。删除对原作者用户名、Ultracool Sheet 路径的隐含依赖，提供明确的站点示例与缺项提示。一般使用者不应需要修改源码模块。

### 2.2 输入示例（设计接口，名称在实现时统一）

```python
# ------------------------------------------------------------------------
# 01. Input and output paths / 输入与输出路径
# ------------------------------------------------------------------------
CATALOGUE_PATH = "/path/to/targets.csv"
WORK_ROOT = "/fred/<project>/<user>/askap-work"
PRODUCT_ROOT = WORK_ROOT + "/products"

# ------------------------------------------------------------------------
# 02. Catalogue column mapping / 输入列名映射
# None means that this optional column is not supplied.
# None 表示未提供该可选列，不是名称为 'None' 的列。
# ------------------------------------------------------------------------
CATALOGUE_FORMAT = "csv"       # csv / fits
CATALOGUE_FITS_HDU = 1          # 仅 FITS 使用
CATALOGUE_COLUMNS = {
    "source_name": "Name",
    "ra": "RA",
    "dec": "DEC",
    "pmra": None,
    "pmdec": None,
}

# ------------------------------------------------------------------------
# 03. Coordinates / 坐标
# Decimal degrees: RA_UNIT='deg', DEC_UNIT='deg'.
# Sexagesimal: RA_UNIT='hourangle', DEC_UNIT='deg'.
# 赤纬度分秒仍是角度，不是小时。
# ------------------------------------------------------------------------
RA_UNIT = "deg"
DEC_UNIT = "deg"
COORDINATE_FRAME = "icrs"
COORDINATE_EPOCH = "J2000"
PM_UNIT = "mas/yr"
PMRA_INCLUDES_COSDEC = True
```

第一版明确支持 ICRS 坐标；不得把未实现的参考系转换伪装成可用配置。坐标历元是输入坐标的参考时间，与观测时间是两个不同概念。逐源历元如需支持，应通过可选列映射显式实现并测试。

## 3. 表格、源名称和 Processing_Index

### 3.1 输入要求

- 必需字段只有源名称、RA、Dec。
- 不再读取或要求 `UCS`、`UCS_name`、`sptnumabs_formula` 等特定字段；原表可通过列映射使用。
- 完全移除光谱型阈值及由其派生的 UCD eligible 筛选。
- 自行未配置时采用零自行；已配置列必须存在。列内缺失或非法值不得静默变为零，应报告对应源与字段。第一版以明确报错为默认，后续如需缺失值策略再单独定义。
- 内部坐标统一为十进制度。接受十进制度及带冒号、空白或单位的时分秒/度分秒字符串；按配置解释，不猜测无单位 RA 是小时还是度。

### 3.2 索引与输入快照

读取表格后、任何筛选之前，按原始数据行顺序添加 `Processing_Index=1..N`。表头不计入编号；无观测或查询失败不导致后续行重编号。

生成 `state/input_catalogue.csv`，保留原始列并添加原始名称、规范化名称及转换后的坐标；不覆盖用户文件。生成列与原表已有同名列冲突时应明确检测，不覆盖原数据。输入快照应保留字符串名称中的前导零等内容。

- `--begin/--end` 按 Processing_Index 选择，包含两端。
- 默认不指定范围时处理全表；可提供按源名称选择的入口。
- 编号只用于顺序与选择，不能成为唯一的持久身份。
- 同一工作区恢复时使用被冻结的输入映射；输入重排或改名不能无声改变旧任务身份。
- 不同 catalogue 使用独立工作目录。输入表变化应明确检测；第一版不实现复杂的跨表合并迁移。
- 全表共享索引不受本次 begin/end 限制，范围外伙伴仍纳入共享处理。

### 3.3 名称规范化

保留 `Original_Source_Name` 与用于目录的 `Source_Name`。空格及其他空白字符转换为 `_`，具体连续空白转换规则固定并记录。不得保留路径分隔符、路径穿越名称或控制字符。

拒绝空名称、重复名称、规范化后冲突（例如 `Source A` 与 `Source_A`），指出相关行号；不自动追加行号隐藏冲突。内部保留区如 `_shared` 也不得与源目录冲突。

对其余特殊字符进行实际兼容检查：Python 参数列表安全不代表 DStools 内部的 shell 命令同样安全。为第一版定义明确的可接受名称规则，并对不支持字符给出可理解的提示，不允许程序执行到中途才发现文件名问题。

## 4. 查询与下载策略

| 条件 | 通用版行为 |
| --- | --- |
| 数据类型 | 固定 visibility，服务于现有 MS 处理链 |
| `t_exptime` | 可配置，默认严格 `> 500` 秒；None 表示不限制 |
| 最小 SB | 默认 None，移除强制 `SB >= 10000`；配置值为包含端点的最小编号 |
| 排除 SB | 可配置列表，默认空；移除硬编码排除 SB65478 |
| 质量等级 | 默认 GOOD、UNCERTAIN，可配置 |
| 文件大小 | 保留现有默认上限 `50*1024*1024 KB` 与单位约定；可配置，支持 None |
| 初始半径 | 默认 1 度，可配置 |
| 半功率筛选 | 默认 central，保留 top 控制项 |
| 已发布限制 | 默认仅公开数据；第一版不扩展未发布数据授权流程 |
| 同 SB 多条记录 | 完成可用性筛选后选离目标最近的记录；保持当前选择策略 |
| 查询上限 | 保留可配置 TOP 上限和截断检测，不将截断结果视为完整索引 |

central 为频率上下限的算术平均，不是平均波长的倒数。保留参考 FWHM=1.2度、参考频率=1.4GHz；可用半径为 FWHM/2 按频率反比缩放。修改频率模式或筛选参数时必须识别旧索引不匹配，不能把旧选择结果标注成新设置。

将公开性筛选放在最近记录选择之前，避免最近记录未公开导致同 SB 其他可用记录也丢失。非法频率/坐标及大小等筛选规则应有统计或原因记录。

不改变已经验证的下载方式：每个 SB 的完整 URL 集合一次传给 `download_files()`，包括 tar 与 checksum；保留已实现的签名 URL 编码处理。命令行 tar 解压成功后删除 tar，保留 checksum，MS 放入目标观测目录。重试时的定向删除遵守既有明确重试规则。

## 5. 观测时间与自行修正

**彻底移除 `All_combine_data_unrepetition.csv` 以及固定默认观测日期。** 不保留隐式兼容回退。

时间来源优先级：

1. CASDA 有效观测时间，保持与既有流程的观测时刻约定一致（优先有效 `t_min`）。
2. CASDA 缺失或非法时，在计算节点从对应 MS 元数据自动读取有效时刻；明确 MS 时间尺度、单位以及转为 MJD 的规则。
3. 需要非零自行修正且仍无法得到时间时，将该源—观测记录为失败，原因明确为“无法取得观测时间，不能进行自行修正”。保留输入并继续独立任务。

记录使用的观测时间、来源（CASDA/MS/unavailable）和坐标参考历元。不需要自行修正的目标，不因观测时间缺失而被这一检查阻断；后续工具若有其他元数据要求，正常记录其失败。

自行修正后的坐标供目标掩膜、extract 和 I/V 裁剪一致使用。共享目标的时间/自行失败是该目标的失败，不能使其他可处理目标无条件失败。

## 6. DStools 参数与共享模型

### 6.1 参数开放边界

集中配置正式 SIF 中实际支持的、适合本处理链的非交互式 CLI 选项。实现时对照 SIF 的 `--help` 与源码，不仅依据本地 dev 源码；优先完整长选项，避免重复短选项歧义。

| 步骤 | 配置范围及固定行为 |
| --- | --- |
| preprocess | 保留 ASKAP 必需修正；现 CLI 无科学选项，说明 FIELD_OLD 与恢复行为，不虚构参数 |
| create-model | 图像尺寸、像素、ASKAP band、迭代、mgain、阈值、robust、数据列、通道数、谱项、多尺度、非交互掩膜、UV 截止、线程、内存及受支持并行选项 |
| insert-model | 非交互目标保护掩膜半径等；位置按各目标自动计算 |
| subtract-model | **固定生成独立 `.subtracted.ms`，不开放关闭选项** |
| extract-ds | 数据列、最短基线、flag、基线平均、主波束校正及日志；检查与减源输出相容性 |
| crop | I/V 裁剪尺寸与单位；同时生成两者 |

不加入交互窗口、手画掩膜等参数。输入 MS、各目标坐标、输出 DS、模型目录及临时目录由流程自动管理；不能让随意改前缀破坏产物发现约定。ASKAP 所需之外的望远镜专用选项不开放。

可选外部掩膜/主波束文件必须预先配置可访问路径，计算节点不在线下载、不等待人工选择；目标相关文件不能错误地全表共用。

### 6.2 独立性和版本记录

公共区保留原始输入，复制执行 preprocess/create-model。每个目标取得**预处理后的 MS 独立副本**和完整模型副本，从 insert 开始处理；不使用硬链接。公共模型不执行 insert、减源或目标裁剪。

模型身份包含观测唯一标识、SIF SHA256 和所有影响模型的参数（包括外部掩膜身份）。配置支持显式成像中心时，不同中心必须区分模型，不能错误共享。

每个准备好的任务保存有效配置快照；排队期间编辑 config.py 不改变该任务。结果保留实际使用的配置/模型版本及容器身份。

## 7. 已完成记录、重试与显式重算

**修改建模或其他科学参数，不自动重算已完成观测。** 普通运行继续跳过成功记录；如果之后出现新增观测，只处理新增部分。

- `--retry-existing` 仅处理符合既有政策的失败记录，不重算成功结果。
- 设计独立显式选项 `--rerun-completed`（拟定名称），按所选源和可选观测范围重算成功记录。
- 显式重算范围不能因共享关系无声扩展到范围外已经成功的伙伴。
- 未完成/失败任务使用本次选定配置，不能复用参数不匹配的模型或中间结果；活动任务恢复继续使用其冻结配置。
- 旧成功产物保留原参数版本，新任务记录新版本；差异只提示，不自动调度重算。
- 显式重算的旧成功产物和记录应保留到新结果成功，避免重算失败后丢失原结果；具体尝试目录和发布方式由实现确定。

失败重试保留既定有限流程：显式请求后从 preprocess 开始完整重试一次；再次失败则清理该重试对象的 MS/对应 checksum，回到登录节点重下载一次；重下载后仍失败则耗尽。共享公共数据不得因单目标私有重试误删。

完成判定以源—观测为单位，要求对应 DS、I、V 都存在并已保存到产物位置。数据库必须保留完成与已验证传输状态，以区分已传输后有意清理和意外缺失。输入清理失败与科学产物完成分别记录，不因清理失败重复科学计算。

同步检查下载、解压、共享准备、worker、恢复、重试、清理、进度导出、Ada 拉取与测试中的路径假设。

默认 4槽×8 CPU、160G 总内存、10G tmp；CPU、内存、线程及工具并行参数应一致。MS 和大模型留在持久工作区，tmp 用途明确。用户的交互式验证申请仍使用最多8CPU、2小时；生产 sbatch 不受这个测试约定代替。

## 9. 观测总表与处理进度

### 9.1 已有基础与需要补齐的部分

现有 crosscatalogue CSV 记录查询与共享关系；`sb_processing.sqlite` 记录步骤状态、失败、耗时及重试。现有观测 CSV 尚未合并处理进度，不能直接作为完整的用户进度总表。

继续以 SQLite 为程序状态依据，新增自动导出的 `state/observation_progress.csv`，供 TOPCAT 与其他表格软件读取。CSV 是可再生成的展示快照，不作为用户手动修改任务状态的入口。

### 9.2 行与列的定义

每行对应一个源的一次选定观测，关联键为稳定源标识与观测唯一标识，同时显示 SB/beam。共享一个观测的三个目标占三行，因为各自拥有独立 DS/I/V。

全表查询结束后即纳入所有选定记录，包括范围之外尚未处理的目标。尚无数据库处理记录时通过查询索引关联显示“未开始”，不必等待下载才显示。

| 列组 | 主要内容 |
| --- | --- |
| 身份 | Processing_Index、原始名称、规范化名称、SB、beam、观测唯一标识 |
| 查询 | 查询状态、频率范围/模式、距离、共享数、索引版本、是否保留旧查询结果 |
| 总体状态 | 未开始、准备中、排队、运行、完成、失败、重试耗尽 |
| 步骤 | tar/checksum下载、解压、观测时间解析、自行修正、preprocess、create、insert、subtract、extract、crop I/V、产物保存、清理 |
| 诊断 | 当前/失败步骤、失败原因、日志路径、重试次数、更新时间、耗时 |
| 追溯 | 观测时间及来源、输入历元、实际参数版本、SIF/模型版本、是否模型复用 |
| 结果 | DS/I/V 路径及产物状态；传输状态按已确认回执展示 |

步骤值：Y=成功，N=失败，空白=尚未执行，NA=确实不适用。不能以空白冒充失败；零自行修正可以为 NA。模型复用的步骤注明来源，不冒充每个目标各自运行一次 create。

没有观测、查询失败或尚未查询的源保留在源级表中，不构造虚假的观测行。查询更新后移除的观测不能擦除历史处理记录；区分“当前索引是否包含”与“历史处理状态”。

### 9.3 总数与导出

汇总至少给出：

- 总源数、可用源数、无观测源数、查询失败与未知源数。
- 当前索引的源—观测总数（预期独立目标产物组数）。
- 去重观测总数（共享建模组数）。
- 未开始、准备/排队/运行、完成、失败、重试耗尽数量。
- 共享组数、受益源数、导出时间与索引版本。

成功进度以完成数为分子；失败不能计为成功。查询未全部成功时，观测总数注明是目前已知数量，不宣称全表完整。历史不在当前索引的记录单独统计，不混入当前进度分母。

并行 worker 只更新数据库。由单一导出端定期、观测/作业完成及正常退出时生成一致快照，通过临时文件替换避免读取半份 CSV。避免每个步骤都重写数万行总表。controller 意外退出时，以数据库为准，恢复或只读进度命令可重新导出；显示最后导出时间。

提供简明进度查看入口和保留 `show_failures` 功能，不要求使用者自己写 SQLite 查询。CSV 使用标准单行列名，列解释与单位放到配套说明文件，保证 TOPCAT 可读取。

## 10. 传输与空间清理

保留 Ada→Ozstar SSH 拉取方向。Ozstar 计算完成不意味着能主动推送到 Ada；Ada 端一键拉取所有完整产物，并自动校验三件套和记录回执。

适配新 `<Source_Name>/SB...` 路径及通用名称解析，不再要求 UCS/LongObs。同一观测只有 DS/I/V 全部校验成功才记录传输成功；记录各文件状态，支持后续空间清理审计。测试失败不删除源产物。

站点路径配置化；本用户的 Ada 实际根目录保持 `/PATH/TO/ada/`。其他用户自行配置其可写目录。
