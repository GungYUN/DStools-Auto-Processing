## 1. 目标与定位

用户输入一个位置，程序自动查询 ASKAP 观测并先返回可检查的表格。用户查看结果后，通过第二条命令自动完成下载、Slurm 提交及完整 DStools 处理。

单源工具不要求 catalogue，不建立全表源索引，不搜索其他目标共享模型。它适合单个目标的研究、诊断和详细数据保留，只处理 ASKAP 数据。

推荐作为同一项目中的独立命令行入口，共用已验证的查询、下载和科学处理模块。底层功能通过显式参数调用，**不得依赖或隐式导入批量 `config.py` 的运行设置**。最终是否独立打包可在实现时确定，不应因此复制一套长期分叉的处理代码。

## 2. 已确认的关键约定

1. 两步流程：`query` 查询并保存表格；`run` 使用保存结果下载及自动处理。
2. 第一步不下载 MS/tar，不提交计算任务。
3. 默认每个 SB 只处理距离目标最近的合格 beam。
4. 可同时指定多个 SB，使这些 SB 处理全部合格 beam；未指定的 SB 仍处理最近的一个。
5. 指定多 beam 的参数是扩展规则，不是“只处理这些 SB”的筛选规则。
6. 查询表保留不同 beam，并显示 `Within_Radius` 等筛选字段。
7. 登录节点联网下载，计算节点运行 DStools；不同 SB/beam 可以并行。
8. 默认保留下载、输入、处理副本、模型、减源 MS、图像、DS 和日志，不执行批量模式的自动清理。
9. 裁剪另存为 cutout，不覆盖完整视场 I/V FITS。
10. 不引入交互式窗口或手动画掩膜；不要求逐观测手动修改命令。

## 3. 命令行使用模型

本文的 `askap-source`、选项和新文件名均为拟定接口；实现后统一更新帮助及文档。以下命令不能被当作当前已存在的工具。

### 3.1 第一步：查询

```bash
askap-source query \
  --ra 180.1494 \
  --dec -28.6159 \
  --name MySource \
  --work-dir /path/to/MySource
```

时分秒输入示例：

```bash
askap-source query \
  --ra "12:00:35.856" \
  --dec "-28:36:57.24" \
  --ra-unit hourangle \
  --dec-unit deg \
  --name MySource \
  --work-dir /path/to/MySource
```

解析器必须正确接受负赤纬；必要时帮助示例使用 `--dec=-28:36:57.24`，并测试实际命令解析。

- 必需输入为 RA、Dec 和工作目录。
- 默认单位为度；RA 支持 hourangle，Dec 支持十进制度和度分秒字符串。
- 内部统一使用十进制度，保留原始输入及单位。
- 名称可选，未提供时根据坐标自动生成并持久保存；精确坐标单独存储，不从舍入后的名称恢复。
- 名称空白规范化为 `_`，检查路径字符与工具内部命令兼容性。
- 可选自行与坐标参考历元通过参数输入；不要求光谱型或 UCD 编号。

成功后输出观测表路径、查询条件、候选与合格记录数、SB 数、默认处理数量及默认选择的预计下载大小。明确说明：默认每个 SB 仅处理最近的合格 beam。

查询失败、结果达到截断上限或结果尚不完整时，不能显示“无观测”或假称成功。完整查询确实没有合格记录时，正常返回零条可处理记录及筛选说明。

### 3.2 第二步：自动下载和处理

```bash
askap-source run \
  --work-dir /path/to/MySource \
  --submit
```

指定 SB 扩展到全部合格 beam，并使用四路并行：

```bash
askap-source run \
  --work-dir /path/to/MySource \
  --all-beams-for-sb 35429 21677 \
  --parallel-slots 4 \
  --submit
```

第二步读取已保存的查询快照，不默认重新访问 TAP 改变观测集合。CASDA 数据 staging 和下载 URL 的重新获取仍可进行；科学选择的观测身份不能无声改变。

执行前自动保存本次选择、参数和资源计划，打印摘要，然后按用户命令继续；不要求额外人工确认每条观测。提交选项缺省时的行为必须清晰定义，不能意外提交。

如实现查询更新或仅预览运行计划的选项，应显式命名并记录查询版本；活动作业始终读取原快照。

## 4. 查询与 beam 选择

### 4.1 查询条件

复用通用版经过验证的 ASKAP 查询规则，通过单源 CLI 默认值/选项提供，不读取批量配置：

- visibility 数据类型。
- 可配置曝光阈值，默认严格 `t_exptime > 500` 秒。
- 可配置质量等级，默认 GOOD/UNCERTAIN。
- 仅公开数据的默认策略。
- 可选最小 SB，默认不限制；排除列表默认空。
- 可配置文件大小上限，默认保持既有数值。
- 默认 1 度初始候选半径。
- 默认 central 频率半功率筛选，保留 top 选项。
- 查询上限与截断检测。

半功率半径使用既有 ASKAP 标定约定：参考 FWHM=1.2度、参考频率=1.4GHz，可用半径为 FWHM/2 按频率反比缩放。central 是上下限频率的算术平均。

“查询所有观测”指查询条件范围内的观测，不表示绕过曝光、质量、大小、公开性或半径限制。表格说明必须给出完整条件。

### 4.2 保留候选，不提前丢失其他 beam

不能直接使用已经执行“每个 SB 只留一行”的查询结果作为单源缓存，否则第二步无法扩展到同 SB 的其他 beam。

底层应分开：取得候选 → 计算可用性与半径 → 标注最近记录 → 执行选择。保留查询返回的 beam 候选与拒绝原因；在服务器端条件已经排除的记录不在候选表中，不能声称其也被列出。

“合格 beam”必须通过所有启用条件且 `Within_Radius=True`。指定多 beam 不绕过这些条件。非法频率或坐标不能假定在半径内；表格应区分不可判定与明确在半径外，并将该记录设为不合格。

可用性筛选（包括公开性）先于最近 beam 选择，避免最近但不可下载的一行阻挡其他合格行。

### 4.3 多 beam 参数的精确定义

| SB 情况 | 处理规则 |
| --- | --- |
| 未列入 `--all-beams-for-sb` | 处理最近的一个合格 beam |
| 列入 `--all-beams-for-sb` | 处理该 SB 的所有合格 beam |
| 指定 SB 不在快照中 | 下载前报告具体编号并停止本次计划，防止拼写错误被忽略 |
| 指定 SB 没有合格记录 | 下载前报告筛选原因，不强制放行 |

允许一次输入多个编号，建议接受数字或 SB 前缀并规范化、去重。空选项值和非法编号应报错。

默认最近选择以角距离最小为准；相同距离使用稳定规则，不依赖服务返回顺序。对重复元数据行按数据集身份去重。一个 SB/beam 如出现多个不同数据集，不能无声覆盖同一个目录；其歧义处理需在实现时明确，不将“全部 beam”误作“任意重复行都处理”。

例：查询中共有 SB100、SB200、SB300，用户只指定 SB200。执行 SB100 最近 beam、SB200 全部合格 beam、SB300 最近 beam；不是只运行 SB200。

## 5. 查询表与执行清单

### 5.1 查询表

输出标准 CSV，可由 TOPCAT 直接读取。列名使用清晰名称，单位和定义放到配套说明文件，不在 CSV 开头混入任意注释行。

建议至少包含：

| 字段组 | 主要内容 |
| --- | --- |
| 身份 | Record_ID、SB_ID、Beam、Filename、数据集唯一标识 |
| 空间 | 波束中心 RA/Dec、Separation_deg |
| 时间与频率 | t_min/t_max、Exposure_seconds、频率上下限与中心频率 |
| 半径 | Radius_Frequency_Mode、Radius_deg、Within_Radius |
| 可用性 | 质量、公开性、预计大小、Eligible、Eligibility_Reason |
| 默认选择 | Nearest_In_SB、Default_Selected |
| 追溯 | 查询时间、查询版本、条件签名 |

`Nearest_In_SB` 指最近的合格记录，而非所有候选中的最近记录。

查询表用于查看；第一版不把手动修改 CSV 当作修改执行计划。机器可读快照保存同一信息及执行所需的完整 CASDA 元数据。

### 5.2 执行清单

`run` 根据快照及扩展 SB 选项生成独立执行清单，增加：

- `Selected`。
- `Selection_Reason`，例如 `nearest_eligible_beam`、`all_beams_for_requested_sb` 或未选原因。
- 本次参数快照、输入查询版本、选择 SB 列表和资源计划。

扩展参数改变本次执行选择，不改写原查询表的 Default_Selected。记录拟处理数量与大小，使用户能区分查询候选数和实际任务数。

## 6. 独立参数体系

以 CLI 参数和工作目录内的配置快照为主，`--help` 说明默认值、单位、None/关闭含义与互斥关系。

- query 保存坐标、自行、历元及查询设置。
- run 保存建模、掩膜、提取、裁剪、容器与 Slurm 设置。
- 恢复读取原运行快照，不要求重新输入全部参数。
- 不继承批量 `ASKAP_*` 环境设置来悄悄改变单源行为。
- 凭据可复用明确指定的安全凭据来源，不在快照中保存密码或有敏感签名的 URL。
- 若站点参数过多，可增加可选独立站点配置，定位为容器/Python/Slurm 默认值，不使用批量 config.py；首版是否需要由实现简洁性决定。

科学参数仅开放当前部署 SIF 支持、适合 ASKAP 自动处理链的非交互式选项。完整命令、实际参数和容器身份留档。固定生成 `.subtracted.ms`，不开放破坏下游发现规则的开关。

观测时间遵循通用版规则：CASDA 优先，必要时自动读 MS；不依赖 `All_combine_data_unrepetition.csv` 或固定日期。需要自行修正却无有效时间时，明确记录该观测失败并继续其他独立观测。没有自行时，不因这一时间检查阻断处理。

## 7. 全自动科学处理与数据保留

每个选定数据集的流程：

```text
CASDA staging / 下载 tar 与 checksum
→ 命令行解压为保留的原始 MS
→ 复制为处理用 MS
→ ASKAP preprocess
→ create-model
→ insert-model（目标保护掩膜）
→ subtract-model（独立 .subtracted.ms）
→ extract-ds
→ 单独写入 I/V cutout
→ 更新状态与记录，保留输入和产物
```

具体保留要求：

- tar 和 checksum 下载后保留，不调用批量模式的“解压后删除 tar”。
- 原始 MS 保持不被 preprocess/insert 修改。
- 保留处理 MS、`.subtracted.ms`、完整 wsclean_model、DS 和单独 cutout。
- 不因成功而删除 MS、FITS 或成功日志。
- insert 会修改模型用于保护目标。若需要保留未修改的 create-model 结果，应在独立插入用模型副本上执行 insert；实现时明确目录和副本用途。
- 不自动清理失败目录；重试或重算不得默默覆盖/删除需要保留的旧数据，可采用独立尝试目录。
- DStools 内部可能自行删除临时 MS；实现前核对并记录边界。默认“保留全部科学输入、输出及流程管理的中间数据”不等于无条件保证第三方工具的所有内部临时文件。

对单源移除批量模式的空间回收政策，但仍报告预计大小并正常处理写入失败。单源可以有大量观测，不以“单源”假定无限空间，也不因空间不足擅自删旧数据。

图像裁剪必须从完整图像读取、写入独立路径。可共享裁剪算法，但不能直接调用会原位覆盖 FITS 的路径而损失完整图像。

## 8. 目录建议

```text
<single-source-work>/
  query/
    observations.csv
    observations-columns.md
    query-snapshot.json
    # 完整 CASDA 元数据可用 ECSV 等形式保存
  state/
    source.json
    runs/<run_id>/
      execution-plan.csv
      effective-settings.json
    observation_progress.csv
    jobs/
  observations/
    SBxxxxx_beamyy/
      download/                    # tar、checksum
      raw/                         # 解压后的原始 MS
      attempts/<attempt_id>/
        work/                      # 处理 MS、.subtracted.ms
        wsclean_model/             # 未插入掩膜的建模结果
        insertion_model/           # 如需保留模型原状，使用此独立副本
        products/                  # DS
        cutouts/                   # 独立 I/V cutout
        tmp/
        logs/
  logs/
```

此结构为实施建议，允许在编码时简化；不引入 UCS 或 LongObs。唯一数据集身份必须与目录映射一同保存。attempt/run 设计只服务于恢复、重试及保留已有结果，不创建含义重复的多套状态。

## 9. Slurm 与并行

登录节点运行 query 和下载；run 在数据准备后通过 sbatch 调用计算 worker。计算节点不访问 CASDA，不在线安装依赖。

- 独立并行单位为一个 SB/beam 数据集。
- 同 SB 不同 beam 可以并行。
- 每路有独立 MS、模型、临时目录、日志和状态身份。
- 单源模式无需跨目标共享模型，禁止把不同 beam 的模型误作同一模型。
- 总 CPU=槽数×每槽线程；WSClean 线程/内存限制与申请资源一致。
- 按槽负载估时并在需要时分批，保持时间上限与恢复机制。
- 不承诺单源所有观测一定能在一个作业内完成。

可参考已验证资源组合4槽×8CPU、160G总内存及48h上限；具体单源 CLI 默认值在实现时定稿并明确打印，避免依赖批量配置。槽数、每槽线程、内存、临时盘、耗时估计均可调整。

交互式诊断如需申请资源，沿用8CPU、32G内存、32G临时盘、2小时的验证标准；正常单源 run 使用 sbatch，不要求人工连接计算节点。

## 10. 状态、恢复与失败

记录每个数据集的下载、解压、preprocess、create、insert、subtract、extract、cutout及总体状态。提供人类可读的进度 CSV 和简明查看入口，列出失败步骤、原因、日志路径、耗时和结果路径。

逐步状态建议与通用版一致：Y成功、N失败、空白未执行、NA不适用。完成不能只依据Slurm的COMPLETED，必须核对本流程要求的结果。

- 再次运行默认恢复未完成流程，跳过已完成且匹配原任务身份的结果。
- 避免重新下载已经确认完整的文件；中断的不完整下载不能因文件存在就当成功。
- 不重复提交仍运行、排队或提交状态不确定的任务；恢复使用既有锁和作业核对机制。
- 单个数据集失败不阻止其他独立数据集。
- 普通 run 不无限重试确定失败；历史失败重试和成功重算用明确不同的入口。
- 修改参数不自动重算成功观测；显式重算保存旧成功产物，新的尝试独立记录。
- 保留策略优先于批量重试中的删除策略：不能直接复用会删除 MS/checksum 的批量重试函数。单源如需重新下载，在新尝试/保存位置处理，保留原失败数据。

首次实现不必扩展复杂重试策略；但恢复、有限显式重试和重算的行为必须可理解、可测试，不得用同一个含糊的 force 参数混合不同操作。

## 11. 实现拆分与检查重点

1. 提取不依赖批量全局 config 的输入参数对象及底层查询/执行接口。
2. 分离候选查询、可用性判定、最近选择和多 beam 扩展。
3. 实现 query 子命令、查询表、列说明和机器快照。
4. 实现 run 执行清单、资源计划、下载和 Slurm 调度。
5. 为单源设置明确的保留模式，检查所有调用路径中的删除和原位裁剪。
6. 实现独立尝试、状态和恢复，复用已验证的过程日志与错误处理。
7. 完成测试和帮助，再确认是否需要可选站点配置及独立打包。

重点避免：

- 为了复用代码而在 import 阶段读取批量工作目录、用户身份或参数。
- query 阶段提前最近去重，导致 all-beams 无法恢复其他 beam。
- all-beams-for-sb 被误实现为 SB 白名单或忽略 Within_Radius。
- 多 beam 共用 SB 级目录导致 MS、模型或日志覆盖。
- 原始 MS 被原位预处理，或完整 I/V 被 cutout 替换。
- 成功、失败重试、重算调用批量清理逻辑删除单源保留数据。
- 新参数无声改变已经排队或运行任务的冻结设置。

## 12. 验收要求

### CLI 与无网络测试

- 十进制度/时分秒和负赤纬输入正确，名称省略及规范化可追溯。
- 不需要 catalogue、光谱型、UCS、旧时间 CSV 或批量 config。
- query 不下载 MS、不提交作业，CSV 能被标准读表工具读取。
- 候选包含多个 beam，Within_Radius/Eligible/Nearest_In_SB 标注一致。
- 默认每SB最近一个；多个指定SB全部合格beam；其他SB仍最近一个。
- 半径外/不合格记录不会因扩展选项被放行；指定不存在的SB在下载前被发现。
- 默认选择与实际执行选择分开保存；run 使用被冻结查询集合。
- 所有非交互式命令与部署SIF选项一致，路径和资源参数正确。
- cleanup禁用、原始MS不被修改、cutout独立写入、模型副本互不影响。
- 恢复不重复提交，参数改变不重算成功记录，日志与状态可追溯。

### Ozstar 实际测试

- 单SB单beam完成下载、预处理、create、insert、subtract、DS与I/V cutout。
- 指定一个有多个合格beam的SB验证全部处理，并同时验证另一个未指定SB只处理最近beam。
- 多槽并行测试，核对峰值并行数及CPU/内存申请。
- 人为中断/受控失败测试恢复与显式重试，确认既有数据仍保留。
- 测试CASDA时间缺失后MS回退，以及需要自行但无时间的明确失败记录。
- 比较原始MS处理前后指纹，检查完整FITS与cutout同时存在；这是验证保护行为，不增加常规DS/FITS内容校验。
- 核对查询数、选择数、成功数、失败数与真实产物一致。
